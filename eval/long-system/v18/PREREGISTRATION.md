# RC7 Native Long-System V18 Preregistration

## Question

On a bounded, written system-delivery task, does the candidate preserve the
accepted contract across native
compaction, cold process resume, child delegation, and a later human revision
more successfully than the same DSH execution without Plan Lattice?

## Candidate Boundary

Candidate commit `e343181af25de6bfd3bd2507e52649c46d587706` preserves the
uninterrupted native path and keeps DSH in control of prompt construction, Plan
Mode, Todo, compaction, Session recovery, child prompt delivery, and scheduling.
Automatic control creates no graph, node, checkout, lease, checkpoint, or
second task summary. It treats only a native Session surface replacement,
process resume, delegation, plan-mode transition, or new human authority as a
continuity boundary. After such a boundary it restores the exact anchored root
human-message identities once and blocks protected writes until that native
execution segment is refreshed. The model-authored child prompt remains the
child's first DSH user message with its exact native identity and content. A
full-Lattice child's delegated leaf is anchored outside the agent-writable
workspace against that native child Session identity; cold resume restores the
original leaf or requires a new native delegation instead of borrowing the
parent's newer focus.

V17 is retained as an executed negative and will not be rerun. Native scored 84
at 3/5 stages and the candidate scored 100 at 4/5, but both exceeded the frozen
4,000,000-input-token budget. The retained candidate trace showed the specific
failure this successor treats: after restart it forgot its deterministic route,
re-entered `lattice_route`, `lattice_intake`, and `lattice_open`, then required
repeated refreshes inside one uninterrupted DSH segment.

V18 keeps V17's task, independently validated Foundation fixture, grader,
budgets, model, runtime, stage order, proxy correction, and arm order. It changes
only the candidate and the success criteria that measure that treatment. Before
any paid call, the frozen smoke must run all five process stages for both arms,
including two real Session surface replacements and the native child request
through the same model proxy contract used by the pair.

## Causal Boundary

Both arms receive byte-identical task text, fixture, hidden grader, official
`dsh-v0.1.0-rc.7` host runtime, model route, temperature, process-stage order,
compaction schedule, workspace Bash channel, hidden tool list, and time/token
limits. Every stage runs in a new Harness process against its durable session.
The child is created through the native `subagent/start` path and receives its
exact ordinary DSH delegation message. The sole treatment difference is that
the candidate tarball is installed in its default `activationMode: auto`; the native
arm has no plugin and thus preserves rc.7's manual-continuation behavior.

The task is unchanged from V17. It retains the behavior under test: five staged
implementations, two native compactions, cold resumes, a child that must recover
inherited outcome through native runtime context, and a human revision that
removes an earlier command. The new protocol identity, candidate tree, smoke,
driver, manifest, and all source hashes are frozen before execution. This is a
targeted mechanism and outcome experiment, not a general leaderboard or a
claim about all coding work.

## Registered Analysis

The pair runs once in this order: native, candidate. Each arm has at most 100
agent requests, 4,000,000 observed input tokens, 500,000 output tokens, and one
hour wall time. The frozen task, grader, fixture, candidate package source,
runtime, wrappers, driver, source hashes, stage-message hashes, and five-stage
proxy smoke are bound in `frozen-manifest.json` before any model call. Failures,
partial workspaces, sessions, audit rows, child evidence, and grader output are
retained. Only a pre-registered infrastructure failure before the first model
response permits a replacement run.

The primary candidate gate requires:

1. all five process stages complete in their frozen order;
2. final hidden score is 100 with zero hard-requirement misses and no obsolete
   `checkout` behavior;
3. observed input tokens remain strictly below 4,000,000;
4. persistent Session evidence contains both scheduled native compaction
   summaries and their actual `surfaceOp.replace` messages;
5. material revision, native child lineage, `subagent/start`, and the exact
   model-authored first child user prompt are verified;
6. no `lattice_route`, `lattice_intake`, or `lattice_open` call occurs anywhere
   in the candidate run, which is stronger than checking restart epochs alone;
   and
7. child reporting does not regress between its snapshot and final integration.

Native runs under the same frozen limits and every result is retained, but its
failure to finish 5/5 is a comparative outcome rather than an infrastructure
invalidation. The report records score, requirements, token, duration, and
lifecycle deltas without making native completion a prerequisite for the
candidate gate.

One pair cannot establish statistical uplift, global ranking, or stable-release
eligibility. A failed gate remains a retained result; the candidate, task,
grader, threshold, and source manifest are not edited and rerun under the V18
identity.
